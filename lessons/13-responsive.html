التجاوب: صفحة تعمل على كل شاشة

لا يوجد «مقاس شاشة» بعد اليوم. هناك مدى من ٣٢٠ بكسل إلى ٢٥٦٠. صفحتك يجب أن تُقرأ في كل هذا المدى، والطريقة ليست أن تصنع ثلاث صفحات، بل أن تكتب قواعد تتغيّر.

الشاشة قد تكون هاتفًا صغيرًا أو حاسوبًا كبيرًا. التجاوب يعني أن الصفحة تعيد ترتيب نفسها: عمود واحد على الهاتف، وعمودان على الحاسوب.

قبل كل شيء: هل صفحتك متجاوبة أصلًا؟

افتح صفحتك على هاتفك. إن ظهرت مصغّرة كأنك تنظر إليها من بعيد، فالسبب سطر واحد ناقص في head:

head.html
<meta name="viewport" content="width=device-width, initial-scale=1">

بدونه يفترض الهاتف أن الصفحة بعرض ٩٨٠ بكسل ويصغّرها لتناسب الشاشة. معه، عرض الصفحة يساوي عرض الشاشة الحقيقي، فتصبح قواعدك منطقية.

أولوية الهاتف: ابدأ من الأصعب

الطريقة القديمة كانت: صمّم للحاسوب، ثم أصلح للهاتف. والنتيجة كود متشابك. الطريقة الصحيحة معاكسة:

  1. اكتب CSS للهاتف أولًا، بلا أي media query.
  2. ثم أضف تحسينات للشاشات الكبيرة داخل min-width.

السبب عملي: الهاتف هو الحالة الأضيق، وكل ما ينجح فيه ينجح في غيره غالبًا. أما العكس فتضطر فيه إلى «تفكيك» ما بنيته.

media query: شكلها ومعناها

responsive.css
/* الأساس: هاتف */
.cards {
  display: grid;
  grid-template-columns: 1fr;
  gap: 14px;
}

/* تابلت وما فوق */
@media (min-width: 640px) {
  .cards { grid-template-columns: repeat(2, 1fr); }
}

/* حاسوب وما فوق */
@media (min-width: 1024px) {
  .cards { grid-template-columns: repeat(3, 1fr); }
}

لاحظ أن كل كتلة تضيف ولا تُلغي. ولا تكتب max-width مع min-width بالتبادل، فتصنع شبكة يصعب تتبّعها. اتجاه واحد يكفي: من الصغير إلى الكبير.

ثلاث نقاط توقّف تكفي

المهنة كلها تدور حول ٦٤٠ و١٠٢٤ تقريبًا، وبينهما لا شيء. لا تضع نقطة لكل هاتف في السوق: اكتب تخطيطًا مرنًا (Flexbox أو Grid) واترك النقاط للحالات التي تتغيّر فيها البنية فعلًا — كتحويل عمودين إلى عمود واحد.

مرونة بلا media query

كثير من التجاوب يمكن تحقيقه بأقل من ذلك:

fluid.css
/* كل صورة لا تتجاوز حاويتها */
img {
  max-width: 100%;
  height: auto;
  display: block;
}

/* شبكة تتغيّر أعمدتها تلقائيًّا */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 14px;
}

/* نص يتناسب مع الشاشة بين حدّين */
h1 {
  font-size: clamp(1.5rem, 4vw, 2.5rem);
}

clamp(الأدنى, المفضّل, الأقصى) من أفضل ما أُضيف إلى CSS: النص يكبر مع الشاشة بسلاسة، ولا يصغر تحت حدّ القراءة ولا يتضخّم بلا معنى.

كيف تختبر بصدق

  • أدوات المطوّر (F12) ثم وضع الجهاز، وجرّب 320 و360 بكسل — لا 375 فقط.
  • كبّر الخط في المتصفح إلى 150٪ وتأكد أن شيئًا لا ينكسر.
  • جرّب على جهاز حقيقي، لا على محاكي فقط: اللمس والتمرير يختلفان.
  • اضغط بيد واحدة: كل زر يجب أن يكون كبيرًا كفاية (٤٤ بكسل تقريبًا).

أخطاء شائعة

  • ! نسيان سطر viewport ثم لوم CSS.
  • ! عرض أفقي (تمرير جانبي) بسبب عنصر بعرض ثابت أكبر من الشاشة.
  • ! نصوص صغيرة جدًّا على الهاتف لأنها كُتبت بـpx ثابت.
  • ! استخدام 100vh لأقسام كاملة، فتظهر مسافة في متصفحات الهاتف بسبب شريط العنوان.

تمرينك الآن

٧ دقائق · بلا مشاهدة حل

خذ صفحة «عن نفسي» من الدرس الثامن، واجعلها متجاوبة: على الهاتف عمود واحد، ومن ٧٠٠ بكسل فما فوق يظهر الشريط الجانبي بجانب المحتوى.

أظهر الحل
responsive.css
body { margin: 0; padding: 16px; }

main {
  display: grid;
  grid-template-columns: 1fr;
  gap: 18px;
}

@media (min-width: 700px) {
  main {
    grid-template-columns: 1fr 240px;
  }
}

img { max-width: 100%; height: auto; }

سطر واحد داخل media query نقل الشريط الجانبي من الأسفل إلى الجانب. هذا هو التجاوب في صورته الحقيقية: تغيير في البنية، لا في الألوان.
