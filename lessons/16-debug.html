التصحيح: كيف تقرأ الخطأ وتجده

الخطأ ليس عقابًا، بل جملة يقولها المتصفح عن مكان الخلل. من يعرف أين يقرأها يصلح في دقيقة ما يبحث عنه غيره ساعة.

بكلمات بسيطة — قبل أي تفصيل

حين لا تعمل صفحتك، لا تُصلح ما تظنّه خطأً. اقرأ ما يقوله المتصفح أولًا، ثم اصلح نقطة واحدة، ثم أعد التحميل.

أين يشتكي المتصفح؟

لكل متصفح لوحة تُخبرك بما حدث. في Chrome وEdge وFirefox تُفتح بـF12 أو Ctrl+Shift+I، وعلى الهاتف تُفتح بكتابة about:debugging (في Firefox) أو بتوصيل الجهاز بحاسوب.

داخل اللوحة ثلاثة أماكن تخصّك في هذا الدرس:

  • Console — رسائل JavaScript والأخطاء. هنا تظهر كلمة Uncaught حين يتوقّف كودك.
  • Elements — شجرة الصفحة كما يفهمها المتصفح بعد التنفيذ، لا كما كتبتها.
  • Network — كل ملف طلبه المتصفح: هل وصل، وبأي رمز حالة (200 تعني وصل، 404 تعني لم يجده).
الخطأ الأول لكل مبتدئ

أن يصلح خمسة أشياء في وقت واحد، ثم يعيد التحميل. إن عملت الصفحة فلن تعرف أيّها كان السبب، وإن لم تعمل فلديك خمسة احتمالات. القاعدة: تغيير واحد، ثم اختبار.

كيف تقرأ رسالة الخطأ

الرسالة تبدو طويلة، وفيها ثلاثة أشياء فقط تهمّك: نوع الخطأ، واسم الملف، ورقم السطر. الباقي تفاصيل تقنية يمكن تجاهلها في البداية.

Console
Uncaught ReferenceError: pric is not defined
    at total (script.js:12)
    at script.js:20

اقرأه هكذا: «استخدمتَ اسمًا لا وجود له في السطر ١٢ من script.js». الاسم في المثال pric — والحلّ غالبًا حرف ناقص في price.

  • ReferenceError — اسم غير معرّف: خطأ إملائي، أو متغيّر أعلنتَه في مكان لا يُرى منه.
  • TypeError — عالجت شيئًا بما لا يقبله، مثل قراءة خاصية من null.
  • SyntaxError — الكود نفسه مكسور: قوس لم يُغلق، أو فاصلة زائدة.

ثلاثة أخطاء تصنع معظم المشاكل

  1. وسم لم يُغلق: كتبتَ <div> ونسيت </div>. في Elements ستجد بقية الصفحة قد دخلت داخل هذا الصندوق — وهذا أوضح دليل.
  2. قوس لم يُغلق: قاعدة CSS واحدة ناقصها } تُسقط كل ما بعدها. علامة ذلك: التنسيق يتوقّف عند نقطة معيّنة ويُهمل الباقي.
  3. ترتيب التنفيذ: تستدعي دالة قبل أن تُعرَّف، أو تعدّل عنصرًا قبل أن يوجد. الحل: السكربت بعد العناصر، أو انتظار DOMContentLoaded.

CSS لا يشتكي، فكيف تصطاده؟

ورقة الأنماط لا تُنتج أخطاء صاخبة: القاعدة الخاطئة تُهمَل بصمت. لذلك تحتاج أدوات فحص بدل الرسائل:

  1. افتح Elements، واختر العنصر، وانظر لوحة Styles: هل قاعدتك موجودة؟ هل مشطوبة؟
  2. القاعدة المشطوبة تعني أن قاعدة أخرى أقوى غلبتها — راجع الأولوية من الدرس التاسع.
  3. لتحديد صندوق عنصر بصراحة، أضف مؤقّتًا outline: 2px solid red — لا يحرّك شيئًا، بخلاف border.
فحص سريع
/* يظهر الحدّ ولا يزحزح أي عنصر */
* { outline: 1px solid rgba(255, 0, 0, .35); }

طريقة تُنهي البحث في دقائق

  1. أعد إنتاج الخطأ أصغر ما يمكن: صفحة واحدة، عنصران، إن عملت فالمشكلة في الباقي.
  2. اقرأ لا تُخمّن: الرسالة تقول السطر؛ ابدأ منه لا من أول الملف.
  3. اطبع الحالة: console.log قبل السطر المشكوك فيه وبعده. إن لم تُطبع الثانية فالكود توقّف بينهما.
  4. ارجع خطوة: احذف آخر تعديل. إن عملت، فأنت وجدت الجاني.
سؤال يوفّر ساعات

بدل «لماذا لا يعمل؟» اسأل: «ما آخر شيء عمل، وما أول شيء لم يعمل؟» الفرق بينهما هو مكان الخطأ تقريبًا دائمًا.

ما ستلاحظه

وسم HTML المكسور لن يُنتج خطأً في Console أبدًا، بل سيظهر خللًا في Elements — وهذا درس بحدّ ذاته: بعض الأخطاء تُرى ولا تُقال. قاعدة CSS المكسورة ستُظهر كل ما بعدها مهملًا في Styles. وأما الاسم الناقص فسيظهر صريحًا في Console مع رقم السطر.
